# Site Report Process

## Purpose

Record a daily site diary entry.

## Role required

Super Admin or Admin.

## Steps

1. [Create the site report](../site-reports/creating-and-editing.md) — date,
   weather, workers on site, works carried out, materials delivered, issues
   and delays.
2. Set the status to Submitted once complete, and Approved once reviewed.
3. Edit the entry later if a correction is needed.

## Expected result

A dated record of site activity that forms part of the project's evidence
trail (useful for delay events, variations, and disputes).

## Linked modules

- [Site Reports](../site-reports/overview.md)
- [Delay and EOT](../delay-and-eot/overview.md) — site reports are useful
  evidence for delay events

## Common mistakes

- Leaving gaps in the site diary — a continuous record is far more useful as
  evidence than sporadic entries.

## What to do next

Reference relevant site report dates when raising a
[delay event](../delay-and-eot/delay-events.md) or responding to an
[RFI](../rfis/overview.md).
