# Delay and EOT Process

## Purpose

Record a delay event and, where appropriate, claim additional time and cost
for it.

## Prerequisites

None beyond the project and, ideally, evidence of the delay.

## Role required

Super Admin or Admin.

## Steps

1. [Record the delay event](../delay-and-eot/delay-events.md) — cause,
   relevant dates, responsibility, evidence.
2. If more time is needed, [submit an EOT request](../delay-and-eot/extension-of-time.md),
   linking it to the delay event.
3. Track the EOT request through Submitted → Under Assessment → Granted or
   Refused.
4. If there is a cost impact, raise a loss and expense claim linked to the
   delay event or EOT request.

## Expected result

A recorded delay event, with a decision recorded on any linked EOT request,
and a generated decision notice once decided.

## Common mistakes

- Raising an EOT request without linking it to the delay event it stems from —
  linking keeps the evidence trail clear.

## What to do next

Update the [Programme](../programme/overview.md) if the EOT decision changes
key dates.
